# Developer Layer

A Windows 11 shell replacement built around a strict no-overlap grid. Every
application and the telemetry panel tile into assigned slots across two or three
displays, with an embedded Nushell workbench and a voice assistant called Atlas.

**Status:** phase 00 — foundations. The workspace, type bridge and slot engine
exist and are tested. Nothing yet manipulates a real window.

## The core idea

Windows never overlap. Each of your daily applications owns a slot, so the
workspace is identical every morning without rearranging. There is no maximise
and no fullscreen by default; minimise is permitted, and every tile is resizable
on both axes.

This single decision removes a great deal of complexity. Because nothing
overlaps there is no transparent overlay canvas, no click-through hit testing,
no desktop-layer window trick, and no focus-policy problem for the embedded
terminal. The telemetry panel is simply a window the slot engine positions
alongside Chrome.

## Architecture

```
crates/
  dl-core          domain types, ts-rs exports, config schema
  dl-platform      ShellIntegration trait — no OS calls
  dl-platform-win  windows-rs implementation (the only crate touching an HWND)
  dl-platform-mac  stub, phase 10
  dl-wm            slot engine — pure logic, unit-testable anywhere
  dl-engine        pass orchestration and engine state across passes
  dl-config        TOML persistence under %APPDATA%
  dl-metrics       telemetry sampling: sysinfo, DXGI, PDH, NVML
  dl-apps          application resolution and icons, phase 04
  dl-atlas         command registry, wake word, speech, phases 07-09
apps/
  desktop          Tauri app: command dispatch and window lifecycle
  ui/shared        generated TypeScript domain types
  ui/design        Atlas design tokens
  ui/shell         React frontend
```

Two rules hold this together:

1. **Only `dl-platform-win` touches an `HWND`.** The slot engine works on plain
   rectangles, so every rule governing your workspace is unit-tested on Linux CI
   and the macOS port becomes an implementation rather than a rewrite.
2. **Rust owns every domain type.** TypeScript is generated by `ts-rs`, so the
   two sides cannot drift. Never edit `apps/ui/shared/src/generated/`.

## Development

Requires Node ≥ 20.11 and a stable Rust toolchain.

```bash
# Pure crates — these run on any platform, including CI
cargo test
cargo clippy --all-targets -- -D warnings

# Type-check the Win32 crate without a Windows machine. cargo check does not
# link, so a Windows target compiles here; only runtime behaviour needs Windows.
rustup target add x86_64-pc-windows-gnu
cargo clippy --target x86_64-pc-windows-gnu -p dl-platform-win --all-targets -- -D warnings

# Regenerate TypeScript after changing a type in dl-core
npm run gen:types

# Frontend
npm install
npm run typecheck
npm run build

# Full desktop app (Windows or macOS only)
npm run desktop
```

`cargo test` deliberately excludes `apps/desktop`, which pulls in Tauri and
needs webkit2gtk on Linux. CI runs `cargo test --workspace` on windows-latest,
which is the first real check for anything touching Win32.
